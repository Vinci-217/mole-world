# 三场景重构 · 验收边界

当前生产范围是摩尔城堡、神秘花海、黑森林，共享连续世界。旧版十二地区实验、八处扩展地点和生成模型不再属于当前生产包。历史地图清单仅作为资料，不表示本次已完成全部地图。

## 已建立的检查

1. 七组 GLB 来源、SHA-256、真实三角数量、法线与坐标检查；Blender 实际回读及开关门射线检查。
2. 从城堡出发的可达性搜索，覆盖三个地区、十处交互点和两座石桥端点的步行高度连续性。
3. Chromium 实际加载七组新模型，验证行走、跳跃、坐下、地图、完整旅程和存档恢复。
4. 昼夜、天气、原版 BGM 播放、照片文件下载、手机方向键、损坏资产显式报错。
5. 实际 WebGL 日间 / 月夜 / 薄雾 / 细雨 / 步行 / 手机截图；不使用效果图替换截图。
6. 白名单生产构建、网站和 Blender 包，发布后逐文件 HTTPS 与 SHA-256 验证。

具体结果记录在 `artifacts/handmade/`；测试结果必须来自当前模型和构建，不能用旧日志代替。

## 美术标准

检查米制比例、建筑开口、角色眼高、材质物理关系、地标轮廓、植被尺度、景别组织、光源方向、夜间可读性、接触关系和天气一致性。修正漂浮、硬穿插、失配背面、单调重复和过曝；特效数量不是验收依据。

“可运行”“模型经 Blender 导出”“功能测试通过”均不代表“已达到 3A”。当前仍需提高建筑装饰、植物变体、地表过渡、动画与远近材质一致性，再由实机画面评审。

## 尚需真实设备的验收

- 目标桌面设备在约 1080p 下，高档争取稳定 30 fps，流畅档争取 60 fps；记录 GPU 型号、DPR、分辨率、浏览器、平均与低位帧率。
- 分别记录初次加载、缓存重载、跨区行走的峰值内存和资源释放；长时间运行无显存持续增长。
- 手机上实际检查发热、内存、触屏与帧率，不能以桌面窄视口测试代替真机。
- 在目标设备检查叶片闪烁、反射、阴影分辨率和 LOD 变化，必要时为不同设备设预算。

云环境 Chromium 使用 SwiftShader 软件渲染，没有独立显卡。本轮 RAF 步进用于功能与图片检查，不能作为硬件性能数据。开发快照中的 `frameMs` 是未经物理步长截断的实际回调间隔；手动步进时它包含等待时间，同样不能当作正常游戏帧率。当前不宣称上述硬件或 3A 画质标准已达成。
